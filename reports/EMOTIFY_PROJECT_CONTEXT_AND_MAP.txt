1. EXECUTIVE SUMMARY & TECH STACK
--------------------------------------------------------------------------------
Emotify is a production mental wellness platform for students and university counselors.
- Mobile App: React Native (Expo SDK 52, Expo Router v4, React 18.3.1)
- Backend: Convex (Real-time TypeScript reactive database, server functions, scheduled actions)
- Authentication: Clerk (Mobile Expo clerk-expo, dashboard clerk-react) mapped to Convex users table
- Web Dashboard: React 18 + Vite + TailwindCSS (Counselor & Admin clinical oversight)
- Testing: Vitest + convex-test + @testing-library/react (Full backend mocking & authz tests)
- AI / LLM: Google Gemini (gemini-1.5-flash primary with mock fallback; model names corrected in P10)

3. AUTHORITATIVE DATA MODEL (KEY CONVEX TABLES)
--------------------------------------------------------------------------------
 1. users:
    - _id, clerkId, full_name, mobile_number, role ("patient"|"counsellor"|"admin"), status ("active"|"inactive"),
      patientId (e.g. STU-001), emergencyContactName, emergencyContactPhone, mitraPreferences, xp (progression).
 2. screeningAttempts:
    - Authoritative questionnaire intake records.
    - instrumentVersions, responses (phq9, gad7, pq16), results (scores, flags, severities).
    - attemptType: "baseline" | "periodic" | "followup".
    - NOTE: WSAS and ReQoL-10 are structurally defined but STRICTLY INACTIVE (pending_approved_content).
 3. triages:
    - Authoritative clinical risk tier.
    - level: "green" | "amber" | "red", suicideFlag: boolean, psychosisFlag: boolean, attemptId.
 4. counsellorAlerts:
    - Critical clinical alerts requiring counselor action.
    - type: "suicideRisk" | "severeDepression" | "psychosisRisk" | "manual_sos" | "triageEscalation".
    - status: "pending" | "acknowledged" | "resolved".
 5. cbtSessions:
    - Interactive, stateful CBT cognitive restructuring session.
    - status: "active" | "completed" | "abandoned" | "safety_mode" | "expired".
    - currentStep: "understanding" | "clarification" | "guided_discovery" | "belief_challenge" |
                   "balanced_thought" | "emotion_rating" | "recovery_coach" | "completed".
    - conversation: message history. Bridges idempotently to reframeLogs on completion.
 6. reframeLogs:
    - Canonical historical saved cognitive reframes.
    - situation_text, thought_original, thinking_trap_choice, guided_answers, reframe_text,
      pre_reframe_intensity, post_reframe_intensity, improvement_percentage, cbtSessionId.
 7. jpmrLogs:
    - Somatic Jacobson's Progressive Muscle Relaxation records.
    - preIntensity (1-10), postIntensity (1-10), durationSeconds, completed: boolean,
      sourceType ("self_initiated" | "routine" | "screening" | "triage"), attemptId, triageId.
 8. microGoals:
    - Non-clinical daily habits & challenge goals.
    - goalId, goalTitle, goalDescription, category, difficulty, points, completed, status ("pending"|"completed"|"skipped").
 9. jpmrVideos:
    - Media storage references (admin-only). No remote CDN URLs. JPMR uses local SVG illustrations.
    - stepIndex, title, storageId (Id<"_storage">). Admin-only mutations.
10. breathingLogs:
    - Paced breathing session records.
    - protocolId, status ("completed" | "partial" | "abandoned"), cyclesCompleted, targetCycles,
      durationSeconds, sourceType, attemptId, triageId. Rate-limited (10/min).
11. groundingLogs:
    - Sensory grounding (5-4-3-2-1) session records.
    - status ("completed" | "partial" | "abandoned"), stepsCompleted (0–5), totalSteps,
      durationSeconds, sourceType ("self_initiated" | "cbt_support" | "crisis_blocker" | "emotion_map").
    - ZERO free-text sensory observations stored.
12. aiCompanionLogs:
    - Authoritative Mitra AI conversation store.
    - Strictly excluded from Clinical Timeline (enforced by LONG-08 test).
    - Raw transcripts gated behind active safety alerts for counselor access (P10 architecture).
13. dailyCheckins:
    - Student daily self-reported mood ("great" | "good" | "calm" | "low" | "anxious").
    - dateStr (calendar date string), streak tracking source.
14. streaks:
    - Consecutive local calendar day check-in streak per student.
15. counters:
    - Monotonic patientId allocator. OCC-safe via Convex STM (hardened in P11 Step 5A).

4. CRUCIAL ARCHITECTURAL INVARIANTS & CLINICAL GUARDRAILS
--------------------------------------------------------------------------------
1. Absolute Clinical Decoupling:
   - Clinical screening scores (PHQ-9, GAD-7, PQ-16) and triage tiers (green/amber/red)
     MUST NEVER be used as inputs for ordinary intervention recommendations (daily habits, CBT, JPMR, breathing, grounding).
   - Clinical scores are NOT injected into Gemini API calls for Mitra.
   - Provenance fields (sourceType, attemptId, triageId) exist strictly for clinical audit and counselor timeline.
2. Non-Fabrication Rule:
   - If an intervention was self-initiated, attemptId and triageId MUST remain undefined.
   - Never query "latest screening" to fabricate provenance on an unlinked session.
3. Server-Authoritative Identity:
   - Every mutation reads userId from `identity.subject` via `ctx.auth.getUserIdentity()`.
   - Client-provided userId arguments in mutations are strictly ignored or rejected.
4. Deterministic Habit Engine:
   - Daily routine micro-goals are chosen deterministically from `common/interventions.ts`
     using user ID + calendar date hash. Zero `Math.random` in production habit selection.
5. Reframe Architecture:
   - `cbtSessions` = active state machine.
   - `reframeLogs` = permanent saved reframe history.
   - Bridge from CBT session to `reframeLogs` is idempotent via the `by_cbtSessionId` index.
   - CBT-linked reframeLogs are deduplicated from the top-level Clinical Timeline.
6. Crisis & Safety Interception:
   - In CBT or Mitra companion, any explicit suicidal ideation or self-harm keywords trigger
     immediate server-authoritative `safety_mode`, generate a `suicideRisk` alert for counselors,
     and show the Tele-MANAS (14416) / 988 Crisis Lifeline. Sessions in `safety_mode` never bridge to reframeLogs.
7. Clinical Timeline is a Dynamic Read Model:
   - `convex/timeline.ts` aggregates 18 source tables dynamically. No materialized timeline table exists.
   - Abandoned interventions (breathingLogs, groundingLogs, jpmrLogs) are excluded.
   - Raw AI dialogue and sensory grounding notes are never exposed in the timeline.
8. Metric Honesty Invariants (P11):
   - Institutional PHQ-9/GAD-7 dashboard stats are labeled as mean scores, NOT "improvements."
   - Synthetic DAU/WAU/MAU formulas (patients × 0.45 etc.) are permanently removed.
   - Student Calm Points count only completed micro-goals (not pending/skipped).
   - Student mood trend is rendered as a discrete 7-day categorical calendar, NOT a continuous line chart.
   - Relaxation telemetry covers JPMR + Breathing + Grounding combined ("Mindful Relaxation Minutes").
9. Mitra Privacy Boundary:
   - Ordinary Mitra conversations are strictly private (never in Clinical Timeline).
   - Only structured safety events (safety_alert_created) appear in timeline under category "safety".
   - Raw chat transcripts in dashboard are safety-gated (viewable only for students with active suicideRisk alerts).
